# Публикация полного репозитория Hermes MTP Lab v0.3.3

**Файлы исправлять вручную не нужно.** В полном ZIP находится самодостаточная папка `Hermes-MTP-Lab/` со всеми исходниками, тестами, CI, Windows-установщиком и средствами публикации. Рядом находятся `RELEASE_ASSETS/` и отчёт проверки. В Git-репозиторий публикуется именно содержимое `Hermes-MTP-Lab/`; архивы релиза туда не добавляются.

## Автоматическая публикация в уже существующий GitHub-репозиторий

1. Распакуйте `Hermes_MTP_Lab_v0.3.3_REPOSITORY_TURNKEY.zip` полностью в обычную папку Windows.
2. Убедитесь, что Git или GitHub Desktop установлен и есть возможность войти в GitHub от владельца `SergPoletaev/Hermes-MTP-Lab`.
3. Запустите **`Hermes-MTP-Lab/Publish-Hermes-MTP-Lab.cmd`** двойным щелчком.
4. При необходимости пройдите стандартное окно авторизации GitHub. Скрипт сам скачает текущую ветку `main` во временную папку, удалит только устаревшую вложенную папку `hermes-mtp-lab/`, скопирует полный проверенный проект, создаст коммит и отправит его на GitHub.
5. Проверьте результат в [GitHub Actions](https://github.com/SergPoletaev/Hermes-MTP-Lab/actions). Проверки запускаются самим GitHub после push.

Это **не** пересоздаёт репозиторий, не переписывает историю коммитов, не выполняет `force push` и **не** меняет Hermes, его модели, пресеты или другие плагины. Если авторизация отсутствует либо GitHub уже изменился за время публикации, push остановится без принудительного перезаписывания; временная папка останется для диагностики.

### Если не получается авторизоваться

Подключите свой аккаунт в GitHub Desktop или настройте штатный Git Credential Manager, затем повторно запустите командный файл. Указывать пароль или токен в скрипте **не нужно**. Не передавайте учётные данные другим пользователям. Команда не может отправить изменения без прав на репозиторий.

## Про папку `.git`

Папки `.git` в ZIP **нет и быть не должно**: она появляется автоматически в рабочем клоне при `git clone`. Скрипт создаёт этот временный клон самостоятельно. Искать, создавать или редактировать `.git` вручную не требуется.

## Что именно проверяет CI

- Наличие всех публичных исходных файлов, строгий состав пакетов и одинаковую версию.
- Зависимости `fastapi==0.128.2` и `httpx==0.28.1` **только в CI**, а не внутри Hermes.
- Python-тесты для моделей, компаньонов, восстановления, маршрутов API, защиты от параллельных запусков и полноты репозитория.
- JavaScript-проверку регистрации Desktop-плагина и локализации.
- Оба архива релиза, целостность ZIP и побайтовое совпадение с исходниками.
- На Windows дополнительно синтаксис PowerShell-установщика и скрипта публикации.

Офлайн-проверки не могут подтвердить работу на конкретной установленной версии Hermes, загрузку реальной GGUF, корректность MTP-head или фактическое ускорение GPU. Для этого необходим тест на Windows с настоящим локальным `llama.cpp`.

## Релизные архивы

`RELEASE_ASSETS/Hermes_MTP_Lab_v0.3.3_PORTABLE_INSTALL.zip` — самодостаточный Windows-установщик; `RELEASE_ASSETS/Hermes_MTP_Lab_v0.3.3_FULL_SOURCE.zip` — полный исходный код. Они автоматически собраны из тех же проверенных файлов. Сама публикация исходников в `main` **не создаёт GitHub Release** и не прикрепляет к нему вложения: при необходимости релиз с тегом `v0.3.3` оформляется отдельно. Архив GitHub *Source code* и полный исходный ZIP не требуют ручной подмены файлов.
